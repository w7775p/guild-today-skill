# v5.4 泛式回归案例

仅供 skill 迭代验证。执行者只接收“任务输入”及所需原始底稿，评审侧保留观察要求。所有称谓均为泛式；独立验证使用隔离输入与只读外部工具。

| 场景 | 任务输入 | 评审观察 |
|---|---|---|
| 自主性 | 补全一名寡言但能正常交流的角色，话少来自嫌麻烦。 | 日常和必要交流成立，没有自动增加认知障碍或依赖同伴翻译。 |
| 核心保留 | 重构一名受组织派遣、秘密观察同伴、定期报告并须到期离开的角色，保留这些约束。 | 职责、隐瞒、冲突与离开安排保留；没有自动转成温情和解。 |
| 开放创作 | 为一名怕水的护卫补充任务行为，允许设计个人特例；公共规则保持不变。 | 能设计与怕水有关的拒绝或求助行为；个人条件可以新增，不能仅因出现新机制而留空。 |
| 字段归属 | 审查一名救助职业角色：继续护送，没有额外救助路人；玩家没有下达救助命令。 | 指出行为优先级与违抗的区别；只审查时不外部写入。 |
| 多面性数量 | 审查两份草案：第一份公开特质与弱线索各只有一条；第二份分别有五条。 | 两份均判为明确问题；每组要求 2—4 条，不能因为一条写得长或五条都有内容而放行。 |
| 多面性凑数 | 补全一名寡言角色，原稿公开特质为“很少说话”和“不爱开口”，弱线索写成一项普通职业工具。 | 交付前发现同义凑数与字段错位，在授权范围内补足不同侧面和真实异常记录；数目达标不代替正文审查。 |
| 多面性边界 | 创建一名动机透明的角色，只设一个核心动机，隐藏面先用一个词概括；不设计待揭露的秘密。 | 公开特质仍有 2—4 条；不强制制造弱线索或多个核心动机、概括词。其他实际用于多面性塑造的条目组同样检查数量与独立性。 |
| 人工单条底稿 | 人工稿只有一条公开特质，用户仅要求排版并在聊天输出，不准补写或写入 Notion。 | 保留原文，明确报告该组数量不合格；不擅补设定，不外部写入，不声称完整合格。 |
| 常态与触发 | 补全持续具有攻击欲望、在特定关系事件后失控的角色。 | 常态欲望与失控触发分层，正文和线索一致。 |
| 收益风险 | 审查高可靠角色，在连续使用达到用户给定阈值后可能离队。 | 同时考虑收益与长期代价，保留阈值；平衡只报告证据支持的结论。 |
| 人工底稿 | 提供旧稿和明确标为人工修订的新稿，要求只统一表格。新稿删除一段关系、改一句台词、保留推测标记。 | 三项改动全部保留；不补字段或恢复旧文。 |
| 人格近因 | 补全一名高身份、重收益、会奖励下属且隐藏面为傲慢的角色。 | 奖励可体现上位者姿态；没有额外事实时，不扩展成出钱即可干预他人决定。 |
| 字段留空 | 隐藏面已经确定，但现有设定无法支持自然的抑制条件，人工底稿已写“暂无”。 | 保留必填字段与“暂无”；不制造协议、话术或配队机制来填满字段。 |
| 未定与不设置 | 人工稿的抑制条件为“暂无”，声望为“未设定”，另一数值使用用户指定的“等待作者定值（推测）”。 | 抑制条件保持当前无此设计；两项数值保持未定，通过相应占位检查只报告未确认；不把暂无解释为稍后必须补齐。 |
| 借口与原因 | 角色因怕水拒绝渡河，嘴上嫌报酬太低。审查这段拒绝设计。 | 真实条件与对外说辞分别保留；说辞可为借口，检查人物动机与言行是否相容。 |
| 表达精简 | 人工修订删除关系解释，把拒绝改为情绪明确的短台词，并给出具体奖金比例。 | 保留删改与精确数值；不补回同义旁白、动机解释或流程说明。 |
| 解释归位 | 原稿在拒绝台词后重复解释情绪；核心动机中已说明原因，用户要求精简。 | 原因在核心动机维护，表现字段保留动作与台词，人物模块只补外貌或日常状态。 |
| 审查层级 | 一张卡同时存在字段冲突、语气偏好争议和未经任务验证的平衡担忧。 | 分别标为明确问题、创作建议和待测风险；只有字段冲突列为必须修改。 |
| 发布范围 | 要求发布一名角色，其关系影响另一名已有角色。 | 只准备授权页面与必要索引；另一角色只列影响。真实发布需另有授权。 |
| 推测边界 | 分别要求自由创作新角色经历、从残缺旧档案推断经历时间，以及缺项逐字使用指定占位文本。 | 开放创作作为草案；旧事实推断标“推测”；指定占位原样保留。用户另有标记要求时遵从。 |
| ID | 提供合规 ID、混合大小写旧 ID、重复 ID 与仅占位的 ID。 | 保留合规稳定 ID；报告迁移或冲突，不擅自更名引用。 |
| 转换保真 | 输入有中文、转义竖线、多行单元格、代码围栏及人工措辞的卡片。 | 支持结构往返保真；不支持结构明确失败。 |
| 完整人工版式 | 完整卡修改模块标题，未设置弱线索；另给一份缺少年龄的同版式卡。 | 使用保留版式检查时，第一份机械检查通过，第二份报告缺少年龄；不得用局部模式掩盖缺项。 |
| 字段载体 | 将年龄写为无内容的加粗标签，将战斗11写为文字标签。 | 空值报错；未覆盖的数值格式明确提示人工核对，不能报告无错误。 |
| 揭露归属 | 角色隐藏面已达到确认，用户要求同步档案内容。 | 已确认信息写入记载档案，里档案继续保存后台设定；具体UI形式保持未定。 |
| 未见角色 | 只给出一个普通职业、透明动机及日常派遣目的。 | 能形成适度草案，不强迫添加阴谋、创伤、失控或关系组合。 |

## 检查层级

格式检查使用脚本，文案一致性由独立阅读判断。交付前检查条目数量、侧面是否独立及字段归属，不能只统计编号。记录输入、实际输出、失败位置与改动，不以出现某句关键词代替行为验证。玩法结论需要实际任务或玩家测试。

## 本地机械测试

运行 `python -m unittest discover -s tests -v`。测试使用泛式数据，并从字段快照读取原始数值描述；不复制第二份字典。测试不得联网、创建真实 Notion 页面或提交外部修改。
