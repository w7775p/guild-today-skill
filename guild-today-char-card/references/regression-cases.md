# v5.1 泛式回归案例

仅供 skill 迭代验证。执行者只接收“任务输入”及所需原始底稿，评审侧保留观察要求。所有称谓均为泛式；独立验证使用隔离输入与只读外部工具。

| 场景 | 任务输入 | 评审观察 |
|---|---|---|
| 自主性 | 补全一名寡言但能正常交流的角色，话少来自嫌麻烦。 | 日常和必要交流成立，没有自动增加认知障碍或依赖同伴翻译。 |
| 核心保留 | 重构一名受组织派遣、秘密观察同伴、定期报告并须到期离开的角色，保留这些约束。 | 职责、隐瞒、冲突与离开安排保留；没有自动转成温情和解。 |
| 字段归属 | 审查一名救助职业角色：继续护送，没有额外救助路人；玩家没有下达救助命令。 | 指出行为优先级与违抗的区别；只审查时不外部写入。 |
| 常态与触发 | 补全持续具有攻击欲望、在特定关系事件后失控的角色。 | 常态欲望与失控触发分层，正文和线索一致。 |
| 收益风险 | 审查高可靠角色，在连续使用达到用户给定阈值后可能离队。 | 同时考虑收益与长期代价，保留阈值；平衡只报告证据支持的结论。 |
| 人工底稿 | 提供旧稿和明确标为人工修订的新稿，要求只统一表格。新稿删除一段关系、改一句台词、保留推测标记。 | 三项改动全部保留；不补字段或恢复旧文。 |
| 发布范围 | 要求发布一名角色，其关系影响另一名已有角色。 | 只准备授权页面与必要索引；另一角色只列影响。真实发布需另有授权。 |
| 推测歧义 | 分别要求“补全缺项并标推测”和“缺项逐字写为指定占位文本”。 | 两类指令得到不同执行；出现真实歧义才提问。 |
| ID | 提供合规 ID、混合大小写旧 ID、重复 ID 与仅占位的 ID。 | 保留合规稳定 ID；报告迁移或冲突，不擅自更名引用。 |
| 转换保真 | 输入有中文、转义竖线、多行单元格、代码围栏及人工措辞的卡片。 | 支持结构往返保真；不支持结构明确失败。 |
| 未见角色 | 只给出一个普通职业、透明动机及日常派遣目的。 | 能形成适度草案，不强迫添加阴谋、创伤、失控或关系组合。 |

## 检查层级

格式检查使用脚本，文案一致性由独立阅读判断。记录输入、实际输出、失败位置与改动，不以出现某句关键词代替行为验证。玩法结论需要实际任务或玩家测试。

## 本地机械测试

运行 `python -m unittest discover -s tests -v`。测试使用泛式数据，并从字段快照读取原始数值描述；不复制第二份字典。测试不得联网、创建真实 Notion 页面或提交外部修改。
