# Role–Task Mapping

本文件负责 Task 创建阶段的角色池读取与角色映射。

它管理内部变量：

`$role_task_map`

用于回答：

`当前角色池中的哪些人物差异值得进入这张 Task`

`这些差异如何转化为派遣判断、后台判定和 Result 差异`

---

# 1.读取当前角色池

Task 创建时读取当前有效角色池。

根据当前 `$task_brief` 与 `$task_design_purpose`，筛选需要深入读取的角色。

常见读取内容包括：

`能力`

`职业`

`经历`

`状态`

`公开特质`

`公开关系`

`角色行为`

`行为优先级`

`关系触发`

`特殊组合`

`角色卡中已有的任务适配、风险提示或类似信息`

`已经揭露的人物信息`

`其他会实际影响派遣与结果的正式人物事实`

---

# 2.建立 $role_task_map

`$role_task_map` 记录当前角色池与当前 Task 的设计连接。

它可以包含：

```text
角色A → 能力优势 / 行为倾向 / 风险 / 关系影响 / 特殊结果可能
角色B → 信息获取 / 状态优势 / 特殊处理方式 / 潜在风险
角色C → 环境适应 / 职业经验 / 资源消耗 / 关系后果
角色A + 角色B → 组合优势 / 优先级变化 / 关系触发 / 风险变化
```

实际内容由当前正式角色事实决定。

---

# 3.任务设计目的已经明确时

当 `$task_design_purpose` 已经由用户明确时：

①围绕该任务设计目的读取角色池。

②筛选能够服务该目的的人物差异。

③建立 `$role_task_map`。

④把这些差异转化为 Task 条件、玩家信息与 Result 需求。

例如当前任务设计目的强调：

`队伍组合判断`

则重点寻找：

`能力互补`

`关系影响`

`行为冲突`

`状态互补`

`特殊组合`

等实际人物差异。

---

# 4.任务设计目的尚未明确时

当 `$task_design_purpose` 尚未确定时：

①先读取角色池。

②寻找能够形成实际派遣判断的人物差异。

③提出适合当前项目阶段的任务设计目的。

④确定 `$task_design_purpose`。

⑤再校准 `$role_task_map`。

角色池可以从以下方向提供任务设计素材：

`能力差异`

`职业差异`

`状态差异`

`行为差异`

`关系差异`

`特殊组合`

`信息掌握差异`

`风险承担差异`

`其他正式人物差异`

---

# 5.角色事实如何进入 Task

角色事实可以映射到：

`任务目标`

`任务环境`

`公开风险`

`推荐能力`

`派遣限制`

`隐藏变量`

`判定输入`

`特殊组合`

`Result 需求`

`后续报告素材`

常见关系例如：

`任务目标 ↔ 角色能力`

`任务环境 ↔ 职业与经历`

`任务风险 ↔ 状态与特质`

`任务中的人物 / 势力 ↔ 角色关系`

`任务冲突 ↔ 行为逻辑与行为优先级`

`特殊条件 ↔ 特殊行为或特殊组合`

---

# 6.玩家派遣依据

角色池映射完成后，检查玩家在派遣前能够看到哪些依据。

可以来自：

`角色公开能力`

`职业与经历`

`公开特质`

`公开关系`

`已有任务情报`

`已经揭露的人物信息`

`任务推荐能力`

`任务风险提示`

Task 需要让当前任务设计目的要求的判断拥有足够依据。

---

# 7.角色优势、风险与特殊表现

Task 可以利用角色池中的：

`明显优势`

`条件性优势`

`稳定风险`

`条件性风险`

`关系影响`

`行为优先级变化`

`特殊处理方式`

`组合表现`

这些内容只有在当前 Task 实际使用时才进入 `$role_task_map` 和后台判定。

---

# 8.指定最佳角色或最佳组合

用户指定：

`preferred_character`

或：

`preferred_team`

时，分析：

①哪些正式人物事实形成优势。

②这些优势在什么 Task 条件下成立。

③玩家通过什么公开信息能够识别优势。

④这些优势如何进入判定与 Result。

任务环境应让指定角色或组合的既有正式事实自然产生对应价值。

---

# 9.Character.特殊组合 与 Task.特殊组合

`Character.特殊组合`

用于跨多个 Task 稳定成立的角色组合规则。

`Task.特殊组合`

用于当前 Task 条件下成立的任务专属组合规则。

Task 可以读取 Character 已确认组合规则，再结合：

`地点`

`目标`

`环境`

`任务特殊条件`

形成当前 Task 的具体组合判定。

---

# 10.批量任务中的角色池使用

一次生成多张 Task 时，为每张 Task 单独建立 `$role_task_map`。

每张 Task 应形成清楚的核心派遣判断。

不同 Task 可以选择角色池中不同的人物差异作为主要设计素材。

---

# 11.验收

检查：

①当前 Task 使用的人物差异是否来自正式角色事实。

②当前 `$role_task_map` 是否服务 `$task_design_purpose`。

③角色优势、风险、关系或组合是否真正进入 Task。

④玩家是否拥有完成当前派遣判断所需的信息。

⑤后台判定是否能够读取这些差异。

⑥Result 阶段是否能够根据这些差异产生实际反馈。
