# Role–Task Mapping

本文件负责 Task 创建阶段的角色池读取与角色映射。

它管理内部变量：

`$role_task_map`

用于回答：

`当前角色池中的哪些正式人物差异会进入这张 Task`

`这些差异如何转化为派遣判断、后台判定和 Result 差异`

---

# 1.读取当前角色池

Task 创建时读取当前有效角色池。

角色池对任务创作的影响强度由：

`$task_brief`

`$task_design_purpose`

共同决定。

常见读取内容包括：

`能力`

`职业`

`经历`

`状态`

`公开特质`

`公开关系`

`角色行为`

`行为优先级`

`关系触发`

`特殊组合`

`角色卡中已有的任务适配、风险提示或类似信息`

`已经揭露的人物信息`

`其他会实际影响派遣与结果的正式人物事实`

角色池规模较大时，根据当前 Task 约束和任务设计目的筛选需要深入读取的角色。

---

# 2.建立 $role_task_map

`$role_task_map` 记录当前角色池与当前 Task 的设计连接。

它可以包含：

```text
角色A → 能力优势 / 行为倾向 / 风险 / 关系影响 / 特殊结果可能
角色B → 信息获取 / 状态优势 / 特殊处理方式 / 潜在风险
角色C → 环境适应 / 职业经验 / 资源影响 / 关系后果
角色A + 角色B → 组合优势 / 优先级变化 / 关系触发 / 风险变化
```

实际内容由当前正式角色事实决定。

---

# 3.角色事实如何进入 Task

角色事实可以映射到：

`任务目标`

`任务环境`

`公开风险`

`推荐能力`

`派遣限制`

`隐藏变量`

`判定输入`

`特殊组合`

`Result 需求`

常见关系例如：

`任务目标 ↔ 角色能力`

`任务环境 ↔ 职业与经历`

`任务风险 ↔ 状态与特质`

`任务中的人物 / 势力 ↔ 角色关系`

`任务冲突 ↔ 行为逻辑与行为优先级`

`特殊条件 ↔ 特殊行为或特殊组合`

---

# 4.玩家派遣依据

完成 `$role_task_map` 后，确认玩家在派遣前能够看到哪些依据。

可以来自：

`角色公开能力`

`职业与经历`

`公开特质`

`公开关系`

`已有任务情报`

`已经揭露的人物信息`

`任务推荐能力`

`任务风险提示`

当前任务设计目的涉及玩家派遣判断时，应提供足够依据。

---

# 5.指定重点角色、目标最佳角色或目标最佳组合

当 `$task_brief` 包含：

`focus_characters`

`target_best_character`

`target_best_team`

时，分别处理：

`focus_characters`
→ 当前 Task 重点考虑这些人物的正式事实与派遣价值。

`target_best_character`
→ 分析哪些正式人物事实能够让该角色在当前 Task 条件下成为最佳单角色答案。

`target_best_team`
→ 分析哪些正式人物事实能够让该组合在当前 Task 条件下成为最佳组合答案。

目标最佳角色或组合需要进一步确认：

①哪些正式人物事实形成优势。

②这些优势在什么 Task 条件下成立。

③玩家通过什么公开信息能够识别优势。

④这些优势如何进入判定与 Result。

---

# 6.Character.特殊组合 与 Task.特殊组合

`Character.特殊组合`

用于跨多个 Task 稳定成立的角色组合规则。

`Task.特殊组合`

用于当前 Task 条件下成立的任务专属组合规则。

Task 可以读取 Character 已确认组合规则，再结合：

`地点`

`目标`

`环境`

`任务特殊条件`

形成当前 Task 的具体组合判定。
