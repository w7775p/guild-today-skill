# Task Field Guidance

本文件负责说明 Task Skill 如何使用当前正式 Task 字段，并记录当前仍未冻结的字段使用边界。

`task-card-fields.md` 保存当前 Notion 字段快照。

本文件保存 Skill 使用方法与字段审查结论。

---

# 1.设计目的

Task 字段：

`设计目的`

定义沿用当前 Notion：

> 说明这张任务主要承担或验证什么设计作用。

Skill 内部变量：

`$task_design_purpose`

用于形成和验收该正式字段。

当任务设计目的涉及玩家决策时，同时明确玩家主要判断与预期任务体验。

---

# 2.判定输入

`判定输入` 是 Task 读取角色池与其他正式状态的主要接口。

可以读取当前 Task 实际使用的：

`角色能力`

`职业与经历`

`角色状态`

`角色特质`

`角色行为规则`

`行为优先级`

`角色关系`

`角色特殊组合`

`参与结算的任务情报`

`任务专属准备`

`世界状态`

`时间状态`

`其他已经确认的正式资产字段`

只记录当前 Task 实际读取的信息。

情报需要区分：

`改变玩家认知`

`参与任务结算`

会直接改变任务执行或 Result 的信息进入判定输入。

---

# 3.特殊组合

`Character.特殊组合`

表示跨多个 Task 稳定成立的人物组合规则。

`Task.特殊组合`

表示当前 Task 条件下成立的任务专属组合规则。

Task 特殊组合可以结合：

`角色`

`队伍`

`地点`

`任务目标`

`环境`

`其他任务特殊条件`

形成当前任务的具体判定。

---

# 4.Result Group 引用

正式字段：

`结果组引用`

当前 Task 内容已经完成、Result Group 尚未建立时，工作状态填写：

`待建立资产后填写`

Result 阶段完成后执行：

`建立 Result Group → 获得稳定 ID → 回填 Task.结果组引用`

最终正式资产应保存稳定 Result Group 引用。

Result Group 当前边界：

`Result.结果事实` 保存后台确认实际发生的关键事实。

`Result.报告素材 / 可揭露事实` 只保存允许交给报告与情报揭露系统使用的信息范围。

最终报告正文与信息组织由报告与情报揭露系统负责。

---

# 5.Event 引用

## 5.1 前置解锁事件

`前置解锁事件`

只保存直接参与 Task 解锁的稳定 Event 引用。

## 5.2 任务内事件引用

`任务内事件引用`

保存任务执行期间可能发生的独立 Event 稳定引用。

只有真实 Task 需要独立 Event 时填写。

Task 不复制 Event 正文。

Event 当前边界：

`Event.事件事实` 保存后台实际发生的关键事实。

`Event.即时玩家反馈` 只有存在通讯、现场交互、即时回报等实际信息渠道时填写。

需要玩家选择的 Event 必须存在让玩家在该时点参与决策的实际渠道。

## 5.3 后续可解锁事件

`后续可解锁事件`

保存 Task 结束后可能关联或解锁的稳定 Event 引用。

# 6.当前仍未冻结事项

## 6.1 非情报型可选准备

当前核心循环包含可选准备。

现有 Task 字段可以承载信息型准备。

真实 Task 出现非情报型准备需求时，根据实际内容确认正式承载方式。

## 6.2 放弃规则公共归属

当前 Task 字段包含：

`放弃规则`

公共默认放弃语义进入 Rules 统一维护时，Task 保存当前任务实际需要的特例。

## 6.3 Time 使用边界

当前 Godot 垂直切片暂不引入正式 TimeSystem、日历或每日刷新。

Task 只有在真实内容出现固定日程、特殊周期或需要稳定引用的特殊时间节点时，才读取并建立 Time 依赖。
