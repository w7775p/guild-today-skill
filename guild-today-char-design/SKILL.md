# guild-today-char-design

版本：v1.1

用于《今日公会照常营业》的角色构思、人物塑造与网页端草案设计。

本 Skill 负责正式角色卡制作之前的人物创作过程。

与 `guild-today-char-card` 的关系：

`guild-today-char-design → 已确认的人物设计 → guild-today-char-card`

`guild-today-char-design` 负责人怎样被塑造出来。

`guild-today-char-card` 负责正式角色卡字段、结构、检查、版本与发布。

本 Skill 不复制或改写 `guild-today-char-card` 的正式角色卡规则。

# 1.工作目标

将用户提供的角色初设逐步塑造成具有鲜明识别度、稳定人物逻辑和具体行为表现的角色。

工作重点：

①提炼人物：从零散设定中找到能够统摄角色的核心形象。

②创造人物：主动提出有意义的创作方向，不能只整理或改写用户原案。

③建立人物逻辑：让动机、隐藏面、公开表现和日常行为能够从同一个人物中自然产生。

④逐步确认：角色设计在聊天中逐层推进，由用户决定采用哪个方向以及下一阶段处理什么。

# 2.真源与职责边界

每次开始或继续工作前，调用并遵守 `global-work-rules`。

本 Skill 不另建角色真源规则。项目真源、字段口径、已有角色事实、人工底稿与冲突裁决统一沿用：

`../guild-today-char-card/references/source-map.md`

涉及正式字段含义时，按该真源映射读取：

`../guild-today-char-card/references/character-card-fields.md`

或真源映射指定的当前正式来源。

字段含义、可见性、必填规则、正式条目数量与角色卡结构由字段真源及 `guild-today-char-card` 裁决。

人物如何被构思、比较、提炼和逐步塑造由本 Skill 负责。

用户已经明确确认的角色事实不得被创意方案擅自改写。

# 3.默认工作流

新角色设计默认按照：

`用户初设 → 必要调研 → 三个角色构想 → 用户选择 / 修改 / 混合 → 继续逐项塑造`

进行。

禁止因为已有角色卡模板就直接机械填满字段。

角色设计没有固定到可以机械推进的唯一下一步。用户决定当前要继续塑造什么。

# 4.调研

用户在当前角色设计任务中明确提到“调研”时，必须进行外部调研。

优先搜索具有较高人气、知名度或长期影响力的娱乐作品，包括游戏、动画、漫画、小说、电影、电视剧等。

调研关注作品怎样塑造与当前角色相近的人物。

重点观察：

①人物怎样被快速建立起来，例如初登场行为、语言、职业、关系、冲突和视觉印象。

②人物最鲜明的特征是什么，重点寻找能够用一个词、成语、四字词语或短语表达的人物印象。

③人物行为怎样证明其性格，寻找实际场景中的选择和行为，避免只整理设定介绍。

④作品如何处理角色的表里差异，观察公开形象、真实动机、隐藏人格以及关键时刻的选择。

⑤有哪些塑造方式值得借鉴或规避，尤其关注人物是否沦为功能角色、套路角色，或依靠其他人物受苦来衬托其魅力。

调研结果只承担参考作用。

三个角色构想可以采用调研中没有出现的方向，只要方案本身成立。

# 5.三个角色构想

以下情况输出三个明显不同的角色构想：

①设计一个新的角色。

②对已有角色进行整体重构。

③用户明确要求重新构思人物方向、提供多个方向或重新设计整个人物。

已有角色的局部修改、单字段设计、局部审查或定点补充，不重新输出三个完整方案，直接处理用户指定部分。

三个方案可以在人物气质、核心动机、隐藏面和人物逻辑上大胆分叉，但必须保留用户已经确认的事实。

每个方案至少包含：

`高识别度词 + 核心动机 + 隐藏面 + 人物逻辑`

## 5.1 高识别度词

高识别度词由 Skill 主动提出，用来直接回答：

“这是个什么样的人？”

优先使用成语、四字词语、描述性短语、社会类型、人格类型、身份称谓或具有明确人物联想的隐喻。

例如：

`道貌岸然`

`天之骄子`

`体面的刀子`

`老好人`

`管家婆`

`亡命之徒`

`刀子嘴豆腐心`

`及时行乐`

`恃才傲物`

高识别度词需要具有生成能力。看到这个词后，应当能够继续想象角色怎样讲话、处理问题、看待别人和应对冲突。

`冷静`、`认真`、`执着`、`聪明`、`谨慎`等普通性格词信息量较低，通常需要继续提炼。

高识别度词属于创作辅助信息，不作为新的正式角色卡字段。

## 5.2 核心动机

每个角色构想都需要给出核心动机，并严格服从当前字段口径。

创作时重点检查：这个动机能否持续解释角色在不同情境中的选择，能否自然生成新的行为。

核心动机保持简洁。人物经历、主题概括和性格评价不能代替核心动机。

## 5.3 隐藏面

每个角色构想都需要给出隐藏面，并严格服从当前字段口径。

隐藏面的核心优先使用一个高密度词或短语概括，例如：

`傲慢`

`怠惰`

`冷漠`

`弑杀`

`依赖`

隐藏面名称同样需要经过人物提炼。普通美德、缺点或性格形容词只有在能够准确统摄这个角色不为人知的一面时才使用。

名称需要让人看到后产生明确的人物联想，并与角色公开形象形成有意义的信息差。`温柔`、`善良`、`坚强`、`脆弱`等宽泛词语本身不构成合格的隐藏面；只有当前角色的具体设计能够证明它就是最准确的概括时，才可以采用。

后面可以附简短解释，说明该词在当前角色身上的实际含义。

隐藏面需要能够继续生成人物行为。是否需要戏剧性秘密由角色本身决定。

## 5.4 人物逻辑

人物逻辑用于解释：

`高识别度词 + 核心动机 + 隐藏面`

怎样组成同一个人。

重点描述：

①她习惯怎样理解事情。

②她最容易注意什么。

③发生冲突时，她通常优先保护什么。

④哪些行为对她而言属于自然反应。

人物逻辑需要能够支持后续公开特质和行为习惯的生成。

这一阶段只建立人物逻辑，不展开完整任务规则。

# 6.三个方案的差异要求

三个方案必须具有真实的创作差异。

禁止把同一个方案换三个形容词、只改变隐藏面名称、只改变措辞，或用轻微程度差异伪装成三个方向。

允许三个方案像三种不同的人，只要它们都能从用户原始设定合理发展出来。

# 7.用户选择后的处理

用户可以选择某个方案、修改方案、混合多个方案、否定全部方案或提出新的方向。

Skill 根据用户选择更新当前已确认的人物设计。

用户选择方案后，只确认已经讨论到的内容。

禁止自动生成完整角色卡。

# 8.“继续下一步”的处理

如果用户明确指定内容，例如：

`继续写公开特质`

`补人物逻辑`

`设计她的行为习惯`

`重新想隐藏面`

直接完成指定任务。

如果用户只说：

`继续`

`继续下一步`

`往下`

`接着做`

先根据当前已经完成的内容列出合理的后续设计项，并确认用户具体要处理哪一项。

例如：

`目前可以继续做公开特质、行为习惯，或者继续调整人物逻辑。你要先做哪一个？`

确认具体目标后，只完成该项。

“继续下一步”不能被解释为“补全角色卡”。

# 9.公开特质设计

公开特质的正式定义与数量要求服从字段真源和 `guild-today-char-card`。

本 Skill 只负责公开特质的创意提炼：

`已有角色设计 → 找到长期稳定的行为共同点 → 提炼名称 → 写具体表现`

公开特质名称本身需要具有足够的信息量，让玩家看到名称时大致理解这项特质。

优秀方向例如：

`体面的刀子`

`全才`

`令行禁止`

`平民优先`

禁止从用户原案里随便抽一个普通形容词作为名称。

例如：

角色设定为：

“所有与亡灵或叛教者有关的任务都会接下，报酬可有可无。”

概括成：

`执着`

属于低质量提炼，因为它没有表达角色执着的对象、态度和人物特色。

角色设计阶段可以一次只设计或确认一条公开特质，不要求为了满足正式角色卡数量立即补齐。

进入完整角色卡制作后，由 `guild-today-char-card` 按正式规则检查公开特质条目数量。已经由用户确认的特质保持原文；数量不足时可以继续提出其他特质，不能为了满足数量改写已经确认的特质。

# 10.行为习惯

当用户要求继续塑造具体表现时，优先设计行为习惯。

行为习惯用于让已经建立的人物逻辑真正出现在场景中。

可以设计：

①交流习惯：角色怎样提问、回答、打断、沉默或表达意见。

②工作习惯：检查装备、写报告、处理证据、准备任务等固定行为。

③压力反应：遇到失败、危险、争执、等待时自然出现的行为。

④生活习惯：与职业、阶层、价值观和性格有关的日常表现。

⑤对人的习惯：角色怎样对待陌生人、弱者、上级、同伴或讨厌的人。

行为习惯需要能够证明角色是谁。

避免用大量随机癖好制造人物感。生活细节只有在确实服务当前人物时才加入。

# 11.人物塑造检查

每完成一个重要设计，可以检查：

①高识别度：能否用少量信息迅速认出这个人。

②统一：核心动机、隐藏面、公开表现和行为是否来自同一个人物逻辑。

③生成能力：已有设计能否自然推导出新的场景行为。

④具体：设计能否落实到角色实际会做什么。

⑤区别：角色是否拥有属于自己的判断方式。

发现问题时直接修改当前设计，无需增加额外字段。

# 12.避免机械复述

本 Skill 必须主动完成创作。

用户原案：

`她会接下所有亡灵相关任务，报酬无所谓。`

低质量处理：

`她很执着。`

这种处理只是压缩信息。

需要继续判断她为什么这样、这种行为让她像什么样的人、什么词能够真正统摄这种人格、它与核心动机和隐藏面有什么关系。

最终产出的内容需要比原始素材多一步人物理解。

# 13.创作范围

创作需要服务当前人物。

新增经历、关系、秘密或其他重大设定需要有人物依据或用户明确要求。

角色可以靠性格、职业、价值观和具体行为成立。

# 14.与 guild-today-char-card 的交接

当用户明确要求：

`写完整角色卡`

`按这个设计制作角色卡`

`转成正式角色卡`

`写入角色卡`

此时进入 `guild-today-char-card` 的职责范围。

正式角色卡制作时，以 `guild-today-char-card` 当前有效版本和正式真源为准。

本 Skill 不自行维护程序字段、完整违抗链规范、全部里档案字段规范、Notion 写入规则、正式版本管理或完整角色卡模板。

字段规则发生冲突时，按正式真源裁决。

创作方法发生冲突时，本 Skill 只裁决人物构思、比较与提炼过程，不改变正式字段含义。

# 15.默认首次输出格式

需要三方案时保持紧凑：

### 方案A｜高识别度词

**核心动机：**

**隐藏面：**

**人物逻辑：**

### 方案B｜高识别度词

**核心动机：**

**隐藏面：**

**人物逻辑：**

### 方案C｜高识别度词

**核心动机：**

**隐藏面：**

**人物逻辑：**

如果进行了调研，在三个方案之前先输出与本次设计直接相关的调研发现。

调研内容只保留能够帮助当前创作的部分。

三个方案输出完成后停止，等待用户选择、修改或提出其他方向。

# 16.核心判断标准

角色设计过程中始终判断：

`这个词能不能让我迅速知道她是什么样的人？`

`这些行为能不能让我相信她真的会这么做？`

`换一个普通角色以后，这套设计还成立吗？`

如果一项内容谁都能用，它通常还没有完成角色塑造。

如果一个概括词无法准确覆盖后面的具体行为，需要重新提炼。

最终目标是：

先创造一个具体的人，再让这个人进入角色卡。
